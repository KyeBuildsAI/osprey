# Osprey 20-day shipping sprint

Target: a polished stakeholder demonstration by 5 September 2026.

## Days 1–3 — Foundation

- Establish repository, quality checks, and deployment path.
- Define incident, evidence, agent, decision, and audit contracts.
- Establish the visual language and representative incident.
- Produce a responsive command-room shell.

Exit: Osprey is recognisable, navigable, and builds reliably.

## Days 4–7 — Working command room

- Add incident creation and selection.
- Add persistent incident state.
- Replace the illustrative map with real map primitives.
- Add evidence detail, filtering, confidence, source, and freshness.
- Add operational timeline and decision workspace interactions.

Exit: a user can enter an incident and understand what is happening.

## Days 8–12 — Option A+ intelligence

- Introduce the durable Temporal incident workflow.
- Add specialist-agent execution and structured outputs.
- Add challenge and disagreement handling.
- Scaffold the Python weather-analysis service.
- Process one deterministic NetCDF rainfall fixture.

Exit: agent and scientific findings flow into the shared operational picture.

## Days 13–16 — Human authority and audit

- Add courses of action with assumptions and trade-offs.
- Add request-analysis, edit, reject, and approve decisions.
- Bind approvals to action payloads and incident-state versions.
- Add a reconstructable audit timeline.
- Add explicit simulation boundaries.

Exit: the complete safe decision journey works end to end.

## Days 17–18 — Evaluation and resilience

- Add representative incident fixtures and expected findings.
- Test unsupported claims, stale evidence, disagreements, and tool failures.
- Test interruption and workflow resumption.
- Address accessibility and responsive behaviour.

Exit: the primary journey is dependable and explainable.

## Days 19–20 — Presentation and shipping

- Polish the interface and empty, error, and loading states.
- Deploy the stakeholder environment.
- Prepare and rehearse a 10–15 minute demonstration.
- Freeze the demo dataset and verify every critical path.

Exit: a repeatable stakeholder-ready demonstration is live.

## Scope guardrail

The demonstration will not send public warnings, contact emergency services,
or control operational infrastructure. External effects remain simulated until
the approval, security, and governance layers are independently validated.
